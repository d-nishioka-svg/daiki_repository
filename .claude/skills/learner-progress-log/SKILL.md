# 学習進捗ログ更新スキル (learner-progress-log)

## このスキルが解決すること

月2回のZOOM定例相談会が終わったあと、その内容を「学習進捗管理スプレッドシート」に手作業で書き写すのは地味に手間がかかるうえ、
書き忘れや表記ゆれが起きやすい。このスキルは、VTT文字起こし・企業名・受講者名を渡されたら、相談内容を要約し、そのままスプレッドシートに
貼り付けられる形の記録文を作成する。

## 重要: このスキルは「記録文を作成する」ところまでで、実際の書き込みはユーザーが行う

以前はClaudeがGoogleドライブのファイル操作やGAS Webアプリへの直接のHTTP呼び出しでスプレッドシートに書き込む方式を試みたが、
どちらも実運用で失敗した:

- Googleドライブ経由でファイル全体を読み書きする方式 → ファイル全体をテキスト化する処理が不安定で実データを壊しかけたうえ、
  レスポンスの出力制限に達して停止した
- GAS Webアプリを外部からHTTPで直接呼び出す方式 → Claude Codeの実行環境のネットワークポリシーでブロックされ、かつ
  会社のGoogle Workspaceポリシー上「匿名アクセス」でのWebアプリ公開自体ができなかった

そのため、スプレッドシート側に `gas/Code.gs` としてメニュー(「学習進捗ログ」→「記録を追加」)を追加する方式にした。
これはスプレッドシートを開いている本人の操作として実行されるため、外部通信もWorkspaceの制限も関係なく確実に動く。
**Claudeがすべきことは、貼り付けるだけで使える記録文を、対象の企業・受講者ごとに分かりやすく提示することまで。**
それ以降(メニューを開く・プルダウンで選ぶ・貼り付ける・書き込むボタンを押す)はユーザー自身の操作になる。

導入(初回のみ)がまだの場合は `gas/DEPLOY.md` を案内すること。

**Googleドライブのファイル読み書きツールや、Webアプリへの直接HTTP呼び出しで自動化しようとしないこと。** どちらも
既に一度試して失敗しており、時間とトークンを浪費するだけで同じ結果になる可能性が高い。うまく自動化できないことに
フラストレーションを感じても、この制約は環境・会社ポリシー側の事情であって、粘ればどうにかなる類のものではない。

## 1. 入力として必要な情報

毎回、以下を受け取る想定:

1. VTTファイル(Zoomの文字起こし)
2. 企業名 — 対象のシートを特定するため
3. 受講者名 — 個別相談なら1名。集団相談の場合は複数名(それぞれの所属企業も添えてもらう。企業をまたぐことがある)
4. 集団相談かどうか — 受講者名が複数渡された場合は集団相談とみなしてよいが、曖昧なら確認する

これらが揃っていない状態で依頼された場合(例: VTTだけ渡されて企業名・受講者名がない)は、内容の要約自体は進めてよいが、
最終的な記録文を「誰宛て」として仕上げるかは、必ず確認してから決めること。

受講者名の特定は、VTT中の発言者名(Zoomの表示名)から自動で行わない。Zoomの表示名とスプレッドシート上の表記が微妙に違うことは
よくあり、自動判定すると本人が間違った企業・受講者を選んでしまう原因になる。ユーザーが明示的に伝えた名前をそのまま使うこと。

なお、実際のシート名・受講者名の一覧は、書き込み時にメニューのダイアログ側でプルダウンから選ぶ形になっている(実物の
スプレッドシートと自動的に一致する)ため、Claude側で企業名・受講者名の表記ゆれを厳密に一致させる必要はない。ユーザーが
伝えた名前をそのまま記録文のタイトル代わりに使えば十分。

## 2. VTTの解析と記録の作成

VTTの内容から、以下のテンプレートで「1回分の記録」を作成する。これは決まったフォーマットが元々なかったため提案したものであり、
報告や進捗確認がしやすいことを狙っている。ユーザーが今後変えたくなったら自由に調整してよい。

```
📅 [実施日]（[個別 / 集団]相談）
【視聴状況】
[動画サービスの視聴進捗について話した内容の要約]
【質問・不明点】
[受講者から出た質問・不明点と、それに対する回答の要約]
【社内改善業務サポート】
[社内改善業務の相談・お手伝いをした内容の要約。話題に出ていなければ「特になし」]
【次回に向けて】
[次回までの宿題・注意点・フォローすべき点]
【備考】
[集団相談の場合、参加者一覧(企業名:氏名)をここに記載。個別相談なら省略してよい]
```

実施日の決め方:

- VTTのファイル名(例: `GMT20260807-...` のような形式)やファイル冒頭のタイムスタンプから日付を推測できればそれを使う。
- 推測できない場合は、ユーザーに実施日を確認する。適当な日付を入れると、進捗管理上の記録として誤りになる。

集団相談の場合:

- 同じVTTから作った同一内容の記録を、指定された受講者全員(複数企業にまたがる場合あり)に向けて用意する(全員分、
  文面は同じでよい)。
- 見出し行に必ず「集団相談」と分かるように書き(上記テンプレートの `[個別 / 集団]` 部分)、【備考】に参加者一覧を入れることで、
  後から見たときにこれが1対1の相談ではなく集団で行ったものだと分かるようにする。

## 3. 内容の確認

記録文が完成したら、書き込む前に必ずユーザーに提示して確認を取る:

- 対象の企業・受講者(集団相談の場合は全員分)
- 記録文の全文

このスプレッドシートは先方企業への報告や受講者本人の進捗確認にそのまま使われるため、誤字や勘違いがあると影響が大きい。

## 4. ユーザーへの引き渡し方

確認が取れたら、そのままコピー&ペーストで使える形にまとめて提示する。集団相談で複数人いる場合は、対象者ごとに
分けて、どの企業・どの受講者向けかが一目で分かるように並べる(文面は同一でよい)。例:

```
--- サンプル商事株式会社 / 鈴木花子 さん ---
📅 2026-08-27（集団相談）
...

--- テスト工業株式会社 / 佐藤次郎 さん ---
📅 2026-08-27（集団相談）
...(鈴木さんと同じ内容)
```

あわせて、「スプレッドシート側で『学習進捗ログ』→『記録を追加』を開き、企業と受講者をプルダウンで選んで、上記を
貼り付けてください」と案内する。まだメニューが表示されていない・初回導入がまだの様子であれば `gas/DEPLOY.md` の
手順を案内する。

## 完了確認

ユーザーが書き込みを終えたら(ダイアログの結果を報告してもらうか、完了した旨を教えてもらったら)、対象の企業・受講者・
集団相談かどうかを簡潔に復唱して、記録として残っていることを確認する。ダイアログ側でエラー(シートが見つからない・
受講者列が見つからない、など)が出た場合は、企業名・受講者名の表記が実物のシートと違う可能性があるので、実際に
シートを見てもらいながら特定し直す。

## 困ったときの対応方針

- VTTの内容が薄く、【質問・不明点】や【社内改善業務サポート】に書くべき内容が実質ない場合は、無理に埋めず「特になし」とする。
- **スプレッドシートへの書き込みを、Claude自身が直接行う方向で自動化しようとしないこと。** Googleドライブのファイル
  操作やGAS Webアプリへの直接HTTP呼び出しは、どちらも既に試して失敗している(詳細は上記)。詰まったら、記録文を
  ユーザーに渡すところまでで良い仕事ができている、と考えて区切りをつけること。
