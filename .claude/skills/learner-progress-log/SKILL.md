# 学習進捗ログ更新スキル (learner-progress-log)

## このスキルが解決すること

月2回のZOOM定例相談会が終わったあと、その内容を「学習進捗管理スプレッドシート」に手作業で書き写すのは地味に手間がかかるうえ、
書き忘れや表記ゆれが起きやすい。このスキルは、VTT文字起こし・企業名・受講者名を渡されたら、相談内容を要約し、該当する企業シートの
受講者列に追記するところまで行う。

## 前提となるスプレッドシートの構造

- 1つのExcelファイル(.xlsx)の中に、企業ごとのシート(タブ)がある。シート名 = 企業名(多少の表記ゆれがありうる)。
- 各シート内に受講者ごとの列があり、列の見出し(1行目など)が受講者名になっている。
- 各列には、これまでの相談記録が上から下に積み上がっている。新しい記録は、その列の既存記録の下(最初の空白セル)に追記する。

このスキルは上記のような「企業シート × 受講者列」の構造を前提にしている。実際に開いたシートがこれと大きく違う場合(例: 受講者が
行方向に並んでいる、企業とシートが1対1でない、など)は、書き込む前に必ず実物の構造を確認し、思い込みで進めずユーザーに確認すること。

## 0. 実行前の確認: スプレッドシートの場所

このスプレッドシートの実体は、ユーザーのPC上でGoogle Drive for Desktop等によりローカル同期された `.xlsx` ファイル。Claude Code は
このファイルを直接開いて編集・保存する。Googleドライブ側の同期の仕組みで自動的にクラウド版にも反映されるので、アップロードなど
Claude側からの追加操作は不要。

- 依頼メッセージの中にファイルパスが含まれていればそれを使う。
- 含まれていなければ、最初にユーザーへパスを尋ねる(例:「学習進捗表のファイルパスを教えてください。例:
  `~/Google ドライブ/マイドライブ/学習進捗管理.xlsx`」)。
- 一度教えてもらったら、同じ会話・セッションの中では聞き直さず使い回してよい。
- 指定されたパスにファイルが見つからない場合は、憶測で似た名前のファイルを探しに行かず、ユーザーに確認すること。似た名前のファイルが
  複数あると、誤って別のファイル(別の版・別会社用など)を触ってしまうリスクがある。

## 1. 入力として必要な情報

毎回、以下を受け取る想定:

1. VTTファイル(Zoomの文字起こし)
2. 企業名 — 対象のシートを特定するため
3. 受講者名 — 個別相談なら1名。集団相談の場合は複数名(それぞれの所属企業も添えてもらう。企業をまたぐことがある)
4. 集団相談かどうか — 受講者名が複数渡された場合は集団相談とみなしてよいが、曖昧なら確認する

これらが揃っていない状態で依頼された場合(例: VTTだけ渡されて企業名・受講者名がない)は、内容の要約自体は進めてよいが、
「どのシートのどの列に書き込むか」を推測で決めず、必ず確認してから書き込むこと。

受講者名の特定は、VTT中の発言者名(Zoomの表示名)から自動で行わない。Zoomの表示名とスプレッドシート上の表記が微妙に違うことは
よくあり、自動判定すると誤った列に書き込んでしまうリスクがある。ユーザーが明示的に伝えた名前を正としてマッチングに使うこと。

## 2. 企業シート・受講者列の特定

1. xlsxスキルの手順に従ってファイルを開き、シート一覧を確認する。
2. 渡された企業名と完全一致するシートがあればそれを使う。ない場合、表記ゆれ(「株式会社」の有無・位置、全角半角、スペースなど)を
   考慮して近いものを探し、「『〇〇』という名前のシートが見つかりませんでした。近いものとして『△△』があります。これでよいですか?」
   とユーザーに確認する。似たものすらない場合、シートを新規作成せずユーザーに確認する。
3. 対象シート内で、渡された受講者名と一致する列見出しを探す。完全一致がなければ、シートの場合と同様に近い候補を提示して確認する。
   列が見つからない場合は、新規に列を追加してよいか含めてユーザーに確認する(単に見落としている可能性も、まだ列が用意されていない
   可能性もあるため)。

## 3. VTTの解析と記録の作成

VTTの内容から、以下のテンプレートで「1回分の記録」を作成する。これは決まったフォーマットが元々なかったため提案したものであり、
報告や進捗確認がしやすいことを狙っている。ユーザーが今後変えたくなったら自由に調整してよい。

```
📅 [実施日]（[個別 / 集団]相談）
【視聴状況】
[動画サービスの視聴進捗について話した内容の要約]
【質問・不明点】
[受講者から出た質問・不明点と、それに対する回答の要約]
【社内改善業務サポート】
[社内改善業務の相談・お手伝いをした内容の要約。話題に出ていなければ「特になし」]
【次回に向けて】
[次回までの宿題・注意点・フォローすべき点]
【備考】
[集団相談の場合、参加者一覧(企業名:氏名)をここに記載。個別相談なら省略してよい]
```

実施日の決め方:

- VTTのファイル名(例: `GMT20260807-...` のような形式)やファイル冒頭のタイムスタンプから日付を推測できればそれを使う。
- 推測できない場合は、ユーザーに実施日を確認する。適当な日付を入れると、進捗管理上の記録として誤りになる。

集団相談の場合:

- 同じVTTから作った同一内容の記録を、指定された受講者全員(複数企業にまたがる場合あり)のそれぞれの列に追記する。
- 見出し行に必ず「集団相談」と分かるように書き(上記テンプレートの `[個別 / 集団]` 部分)、【備考】に参加者一覧を入れることで、
  後から見たときにこれが1対1の相談ではなく集団で行ったものだと分かるようにする。

## 4. 書き込み前の確認

書き込む前に、以下をまとめてユーザーに提示し、確認を取ってから保存する:

- 対象の企業シート名・受講者列名(集団相談の場合は全員分)
- 実際に追記しようとしている記録の全文

このスプレッドシートは先方企業への報告や受講者本人の進捗確認にそのまま使われるため、誤字や勘違いがあると影響が大きい。多少手間でも
一度確認を挟むことで、書き込んでから直すよりずっと安全になる。

集団相談で同一内容を複数人分に書き込む場合、最初の1人分の内容を確認してもらえれば、残りは「同じ内容を◯◯さん・△△さんにも書き込みます」
と伝えたうえでまとめて進めてよい(1人ずつ同じ文面を確認してもらう必要はない)。

## 5. 実際の書き込み

- 既存の内容(書式・他のシート・他の受講者列)を壊さないよう、xlsxスキルの作法(openpyxl等でセル単位に追記し、フォント・列幅などの
  既存書式を保持する)に従う。ファイル全体を作り直すような処理は避ける。
- 追記先は対象列の最後にデータが入っているセルの次の空きセル。途中に空白行があるからといってそこに詰めて書き込まない(相談会ごとの
  区切りを分かりやすくするために意図的に空けている可能性があるため、既存のレイアウトに合わせる)。
- 保存後はローカルファイルへの上書き保存のみでよい。Google Drive for Desktop等の同期に任せるので、Claude側からGoogleドライブへの
  追加のアップロード操作は不要。

## 6. 完了報告

書き込みが終わったら、次を簡潔にまとめて報告する:

- 更新したシート名・受講者名(複数なら全員分)
- 追記した記録の内容(実際に書いたテキスト)
- 集団相談だった場合はその旨と参加者一覧

## 困ったときの対応方針

- ファイルが見つからない、シートが見つからない、列が見つからない、といった「対象が特定できない」場面では、憶測で進めず必ず
  ユーザーに確認する。学習進捗の記録は先方への報告に使われるため、誤った場所に書き込むコストは、後から気づいて直す手間よりずっと大きい。
- VTTの内容が薄く、【質問・不明点】や【社内改善業務サポート】に書くべき内容が実質ない場合は、無理に埋めず「特になし」とする。
- 実際のExcelファイルの読み書き(セル追記・書式保持など)は、このリポジトリ/環境にある xlsx スキルの手順に従うこと。ここでは
  スプレッドシートの中身をどう解釈しどう書き込むかのビジネスロジックのみを扱い、ファイル操作自体を再実装しない。
