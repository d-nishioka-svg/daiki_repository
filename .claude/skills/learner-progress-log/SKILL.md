# 学習進捗ログ更新スキル (learner-progress-log)

## このスキルが解決すること

月2回のZOOM定例相談会が終わったあと、その内容を「学習進捗管理スプレッドシート」に手作業で書き写すのは地味に手間がかかるうえ、
書き忘れや表記ゆれが起きやすい。このスキルは、VTT文字起こし・企業名・受講者名を渡されたら、相談内容を要約し、該当する企業シートの
受講者列に追記するところまで行う。

## 重要: スプレッドシートへの書き込みは必ずGAS Webアプリ経由で行う

**Googleドライブのファイル読み書きツール(`read_file_content` / `download_file_content` / `create_file` など)を使って、
スプレッドシートの中身を直接いじろうとしないこと。** 過去にこの方法を試したところ、ファイル全体をテキストに変換する処理が
不安定で実データを壊しかけたうえ、レスポンスの出力制限に達して停止する、という失敗が実際に起きている。

代わりに、`gas/Code.gs` として同梱されているGAS(Google Apps Script)のWebアプリを経由する。これはスプレッドシートに
直接組み込まれて動くGoogle純正の仕組みなので、ファイルまるごとのやり取りが発生せず、軽くて確実。デプロイ手順は
`gas/DEPLOY.md` を参照(初回のみユーザー側で作業してもらう必要がある。既にデプロイ済みなら不要)。

このWebアプリは2つの操作を提供する(どちらも `POST` でJSONを送る):

- `listStructure` — 全シートのシート名と、各シート内の受講者名(列見出し)一覧を返す。書き込み前に必ずこれを呼び、
  実際のシート構造を確認すること。
- `appendEntries` — 指定したシート・受講者の列に、指定したテキストを1件追記する。集団相談の場合は、同じ内容の
  entry を参加者の人数分まとめて渡せば、まとめて書き込める。

呼び出しには合言葉(SECRET)が必要。実行前の確認(下記0)でURLとSECRETを確定させてから使うこと。

## 0. 実行前の確認: WebアプリのURLと合言葉(SECRET)

1. まず環境変数 `LEARNER_SHEET_WEBAPP_URL` と `LEARNER_SHEET_WEBAPP_SECRET` が設定されていないか確認する
   (例: `echo "$LEARNER_SHEET_WEBAPP_URL"`)。設定されていればそれを使う。
2. 設定されていなければ、ユーザーにURLとSECRETを尋ねる。まだGASをデプロイしていない場合は `gas/DEPLOY.md` の手順を
   案内する。
3. 一度教えてもらったら、同じ会話・セッションの中では聞き直さず使い回してよい。ただし、次回以降のセッションでは
   毎回聞き直しになる点をユーザーに伝え、環境変数として登録しておくと楽になる旨を案内するとよい。
4. `listStructure` を一度呼び出してみて、正しくシート名・受講者名の一覧が返ってくることを確認する。`unauthorized`
   エラーが返る場合はSECRETの入力ミスなので、憶測でリトライを繰り返さずユーザーに確認する。

### 呼び出し方の例(curlの場合)

```bash
curl -s -X POST "$LEARNER_SHEET_WEBAPP_URL" \
  -H "Content-Type: application/json" \
  -d '{"action":"listStructure","secret":"'"$LEARNER_SHEET_WEBAPP_SECRET"'"}'
```

```bash
curl -s -X POST "$LEARNER_SHEET_WEBAPP_URL" \
  -H "Content-Type: application/json" \
  -d @entries.json
```
(`entries.json` の中身は `{"action":"appendEntries","secret":"...","entries":[{"sheetName":"...","learner":"...","text":"..."}]}`)

## 1. 入力として必要な情報

毎回、以下を受け取る想定:

1. VTTファイル(Zoomの文字起こし)
2. 企業名 — 対象のシートを特定するため
3. 受講者名 — 個別相談なら1名。集団相談の場合は複数名(それぞれの所属企業も添えてもらう。企業をまたぐことがある)
4. 集団相談かどうか — 受講者名が複数渡された場合は集団相談とみなしてよいが、曖昧なら確認する

これらが揃っていない状態で依頼された場合(例: VTTだけ渡されて企業名・受講者名がない)は、内容の要約自体は進めてよいが、
「どのシートのどの列に書き込むか」を推測で決めず、必ず確認してから書き込むこと。

受講者名の特定は、VTT中の発言者名(Zoomの表示名)から自動で行わない。Zoomの表示名とスプレッドシート上の表記が微妙に違うことは
よくあり、自動判定すると誤った列に書き込んでしまうリスクがある。ユーザーが明示的に伝えた名前を正としてマッチングに使うこと。

## 2. 企業シート・受講者列の特定

1. `listStructure` を呼び出し、実際のシート名一覧・各シートの受講者名一覧を取得する。
2. 渡された企業名と完全一致するシート名があればそれを使う。ない場合、表記ゆれ(「株式会社」の有無・位置、全角半角、
   スペースなど)を考慮して近いものを探し、「『〇〇』という名前のシートが見つかりませんでした。近いものとして
   『△△』があります。これでよいですか?」とユーザーに確認する。似たものすらない場合、憶測で進めずユーザーに確認する。
3. 対象シート内の受講者名一覧から、渡された受講者名と一致するものを探す。完全一致がなければ、シートの場合と同様に
   近い候補を提示して確認する。見つからない場合は、新規に列を追加するかどうかを含めてユーザーに確認する(この
   Webアプリは既存の列に追記する機能しか持たないため、新しい列が必要な場合はユーザー自身にスプレッドシート上で
   列を追加してもらう)。

## 3. VTTの解析と記録の作成

VTTの内容から、以下のテンプレートで「1回分の記録」を作成する。これは決まったフォーマットが元々なかったため提案したものであり、
報告や進捗確認がしやすいことを狙っている。ユーザーが今後変えたくなったら自由に調整してよい。

```
📅 [実施日]（[個別 / 集団]相談）
【視聴状況】
[動画サービスの視聴進捗について話した内容の要約]
【質問・不明点】
[受講者から出た質問・不明点と、それに対する回答の要約]
【社内改善業務サポート】
[社内改善業務の相談・お手伝いをした内容の要約。話題に出ていなければ「特になし」]
【次回に向けて】
[次回までの宿題・注意点・フォローすべき点]
【備考】
[集団相談の場合、参加者一覧(企業名:氏名)をここに記載。個別相談なら省略してよい]
```

実施日の決め方:

- VTTのファイル名(例: `GMT20260807-...` のような形式)やファイル冒頭のタイムスタンプから日付を推測できればそれを使う。
- 推測できない場合は、ユーザーに実施日を確認する。適当な日付を入れると、進捗管理上の記録として誤りになる。

集団相談の場合:

- 同じVTTから作った同一内容の記録を、指定された受講者全員(複数企業にまたがる場合あり)のそれぞれの列に追記する。
- 見出し行に必ず「集団相談」と分かるように書き(上記テンプレートの `[個別 / 集団]` 部分)、【備考】に参加者一覧を入れることで、
  後から見たときにこれが1対1の相談ではなく集団で行ったものだと分かるようにする。

## 4. 書き込み前の確認

書き込む前に、以下をまとめてユーザーに提示し、確認を取ってから `appendEntries` を呼び出す:

- 対象の企業シート名・受講者列名(集団相談の場合は全員分)
- 実際に追記しようとしている記録の全文

このスプレッドシートは先方企業への報告や受講者本人の進捗確認にそのまま使われるため、誤字や勘違いがあると影響が大きい。多少手間でも
一度確認を挟むことで、書き込んでから直すよりずっと安全になる。

集団相談で同一内容を複数人分に書き込む場合、最初の1人分の内容を確認してもらえれば、残りは「同じ内容を◯◯さん・△△さんにも書き込みます」
と伝えたうえでまとめて進めてよい(1人ずつ同じ文面を確認してもらう必要はない)。

## 5. 実際の書き込み

- 確認が取れたら、`appendEntries` を1回呼び出し、対象者全員分の `{sheetName, learner, text}` をまとめて渡す。
  集団相談なら同じ `text` を人数分並べる。
- レスポンスの `results` を必ず確認する。`status: "written"` 以外(`"error"`)の項目があれば、その理由(シートが
  見つからない・受講者列が見つからない、など)をそのままユーザーに伝える。一部だけ成功・一部だけ失敗した場合、
  成功した分は既に書き込まれている点を明示する(もう一度全体を投げ直すと二重に書き込まれてしまう)。
- ここでうまくいかないからといって、Googleドライブのファイル読み書きツールでの代替(ダウンロード・再構築・
  アップロードし直すような迂回策)を試みないこと。うまくいかない場合は、WebアプリのURL・SECRET・シート構造の
  どれかが想定と違う可能性が高いので、状況を整理してユーザーに確認する方が早い。

## 6. 完了報告

書き込みが終わったら、次を簡潔にまとめて報告する:

- 更新したシート名・受講者名(複数なら全員分)
- 追記した記録の内容(実際に書いたテキスト)
- 集団相談だった場合はその旨と参加者一覧

## 困ったときの対応方針

- ファイル・シート・受講者列が見つからない、`unauthorized` になる、といった「対象が特定できない」場面では、
  憶測で進めず必ずユーザーに確認する。学習進捗の記録は先方への報告に使われるため、誤った場所に書き込むコストは、
  後から気づいて直す手間よりずっと大きい。
- VTTの内容が薄く、【質問・不明点】や【社内改善業務サポート】に書くべき内容が実質ない場合は、無理に埋めず「特になし」とする。
- **Webアプリ経由でのやり取りがうまくいかないとき、ファイル全体を読み書きする方向に切り替えて解決しようとしないこと。**
  それは既に一度、大量の時間とトークンを消費したうえで失敗している方法である。詰まったら早めにユーザーに状況を
  報告し、次にどうするか判断を仰ぐこと。
